## این پروژه چی کار می‌کنه؟

هر اپراتور ایرانی (ایرانسل، همراه اول، رایتل، مخابرات، شاتل، …) فیلترینگ خودش رو داره؛ دامنه‌ای که روی ایرانسل عالی کار می‌کنه ممکنه روی همراه اول بلاک یا کند باشه. برای کانفیگ‌های **Reality** و **XHTTP** انتخاب SNI (دامنه‌ی استتار) مستقیماً روی پایداری و سرعت اثر می‌ذاره.

AX-Scanner یه لیست کاندید می‌سازه، **از اینترنت واقعیِ خودت** تستشون می‌کنه و بهت می‌گه:

- کدوم SNI روی **اپراتور تو** اصلاً وصل می‌شه؛
- کدوم‌ها با **Reality (TCP/Vision)** واقعاً هندشیک می‌شن؛
- کدوم‌ها با **Reality + XHTTP** واقعاً هندشیک می‌شن؛
- و بین اون‌ها کدوم کمترین تأخیر و بیشترین پایداری رو داره.

خروجی یه جدول رتبه‌بندی‌شده برای همون اپراتوریه که تستش کردی.

## چرا «از نت خودت» این‌قدر مهمه؟

بلاک شدن SNI داخل مسیر شبکه‌ی اپراتور و روی بسته‌ی `ClientHello` اتفاق می‌افته. اگه تست رو از روی سرور آلمان بگیری، بسته‌ها اصلاً از اپراتور ایرانی رد نمی‌شن و نتیجه‌ی تست بی‌معناست. این یه محدودیت فیزیکی شبکه‌ست: هر اتصال از همون دستگاهی خارج می‌شه که کد رو اجرا کرده، حتی اگه با SSH بهش وصل باشی.

راه‌حل این پروژه: یه **Probe Client** روی کامپیوتر خودت اجرا می‌شه، خودش به سرور وصل می‌مونه (اتصال خروجی، بدون هیچ پورت‌فوروارد و تونل دستی) و تست‌ها رو **روی همون کامپیوتر** انجام می‌ده. ترافیک تست از داخل هیچ تونلی رد نمی‌شه؛ اپراتور دقیقاً همون چیزی رو می‌بینه که از یه کاربر واقعی می‌بینه.

## معماری

```
   کامپیوتر تو (ویندوز/لینوکس) — روی اپراتور مورد نظر
  ┌───────────────────────────────┐
  │ probe_client.py               │   ① اتصال کنترلی (TLS، فقط دستور و جواب)
  │  • تست TLS به دامنه‌ها        │ ─────────────────────────────┐
  │  • xray-core خصوصی خودش       │                              ▼
  │  • تشخیص IP/ISP واقعی         │                 ┌──────────────────────────┐
  └──────────────┬────────────────┘                 │ سرور تو (مثلاً آلمان)    │
                 │ ② ترافیک تست، مستقیم و            │  • Agent + Broker        │
                 │    از مسیر واقعی اپراتور          │  • منوی AX-Scanner       │
                 ▼                                  │  • سرورهای Reality موقت  │
        دامنه‌های کاندید  /  Reality موقت روی سرور ◄──┴──────────────────────────┘
```

- **Agent (روی سرور):** برای هر تست یه سرور Reality موقت با SNI مورد نظر بالا میاره و بعدش پاکش می‌کنه.
- **Broker (روی سرور):** اتصال دائمی Probe Client رو نگه می‌داره و بهش می‌گه «این تست رو بگیر».
- **Probe Client (روی کامپیوتر تو):** تست رو با شبکه‌ی خودت انجام می‌ده و فقط عدد و نتیجه رو برمی‌گردونه.

## روش تست (دو مرحله‌ای)

1. **مرحله ۱ — فیلتر سریع:** برای همه‌ی کاندیدها (پیش‌فرض تا ۴۰۰ دامنه) چند بار هندشیک TCP+TLS از نت تو گرفته می‌شه: موفقیت، نسخه‌ی TLS، ALPN و تأخیر. DNS هم از سمت تو resolve می‌شه، پس مسموم‌سازی DNS اپراتور هم دیده می‌شه.
2. **مرحله ۲ — تست عمیق:** فقط ۵۰ دامنه‌ی برتر (تا IP سرورت حساس نشه) با پروتکل واقعی تست می‌شن، **هر دو ترنسپورت**: `VLESS+Reality (TCP/Vision)` و `VLESS+Reality (XHTTP)`. یه xray-core خصوصی روی کامپیوتر تو به سرور Reality موقت وصل می‌شه و یه درخواست کوچیک از داخلش می‌گذره؛ یعنی هندشیک کامل و تأخیر واقعی.

**ستون XHTTP در جدول:** برای ۵۰ دامنه‌ی مرحله‌ی ۲ نتیجه‌ی *واقعی* هندشیک XHTTP هست (✅/❌). برای بقیه فقط تخمین از مرحله‌ی ۱ هست و با `~` مشخص می‌شه تا با تست واقعی اشتباه نشه.

**تأیید اپراتور:** قبل از تست، IP/ISP/ASN اتصال *کامپیوتر تو* بررسی می‌شه. اگه اپراتور انتخابی با اپراتور واقعی نخونه (یا VPN روشن باشه) هشدار می‌گیری.

## راه‌اندازی — قدم به قدم

### قدم ۱ — روی سرور (اوبونتو ۲۴.۰۴)

```bash
git clone https://github.com/AtronixX-Core/AtronixX-SNI-Scanner.git
cd AtronixX-SNI-Scanner
sudo bash install.sh
AX-Scanner
```

توی منو گزینه‌ی **۱** رو بزن (نصب Agent). دو تا پورت می‌پرسه: پورت Agent و پورت Probe. اگه پورت **443** آزاده برای Probe همون رو بده؛ شبیه ترافیک HTTPS معمولیه و کمتر مشکل می‌خوره. اگه `ufw` فعاله، پورت Probe رو باز کن.

بعد گزینه‌ی **۲** رو بزن؛ دستور آماده‌ی کامپیوترت همراه توکن نشون داده می‌شه.

### قدم ۲ — روی کامپیوتر خودت (اپراتور مورد نظر)

فقط **Python 3.8+** لازمه؛ نه pip، نه دسترسی ادمین. فایل `probe_client.py` رو از همین ریپو بگیر و **یک بار** با مقادیری که سرور نشون داده اجراش کن.

**لینوکس:**
```bash
python3 probe_client.py --server IP_SERVER --port 41081 --token TOKEN
```

**ویندوز (PowerShell):**
```powershell
py probe_client.py --server IP_SERVER --port 41081 --token TOKEN
```

دفعه‌های بعد بدون آرگومان اجرا می‌شه (`python3 probe_client.py` یا `py probe_client.py`). پنجره رو باز نگه دار. خودش موقع قطع شدن مجدد وصل می‌شه.

- شروع خودکار بعد از ورود به سیستم (اختیاری): `--autostart on` (برای غیرفعال‌سازی `off`)
- **VPN و TUN mode (v2rayN، Nekoray، Hiddify و…) رو خاموش کن.** وگرنه VPN رو تست می‌کنی نه اپراتور رو. برنامه اگه آداپتور VPN ببینه هشدار می‌ده.

### قدم ۳ — گرفتن تست

دوباره روی سرور `AX-Scanner` رو اجرا کن (بالای منو وضعیت Probe Client نمایش داده می‌شه):

- **۳** — تست خودکار (دامنه‌ها رو خودش پیدا می‌کنه)
- **۴** — تست دستی (یه دامنه، لیست، یا فایل `.txt`)

اپراتور رو انتخاب کن، اتصال تأیید می‌شه، تست اجرا می‌شه و جدول نهایی میاد:

| ستون | معنی |
|---|---|
| Connect | مرحله ۱: اتصال TCP+TLS روی اپراتور تو |
| Reality | هندشیک واقعی VLESS+Reality (TCP/Vision) |
| XHTTP | هندشیک واقعی XHTTP (یا تخمین با `~`) |
| Latency / R-Latency | تأخیر مرحله ۱ / تأخیر هندشیک واقعی |

برای اپراتور دیگه: کامپیوتر (یا سیم‌کارت/مودم) رو عوض کن، `probe_client.py` رو اجرا کن و تست رو دوباره بگیر. نتیجه فقط برای همون اپراتور و همون سرور معتبره.

## حذف کامل

**روی سرور** (منو ← گزینه‌ی ۶، یا `sudo bash uninstall.sh`): سرویس، پوشه‌ی `/opt/ax-scanner` (باینری xray، کلیدها، گواهی، توکن، کش)، دستور `AX-Scanner` و هر پروسه‌ی xray مربوط به همین ابزار پاک می‌شه و آخرش یه چک‌لیست تأیید نشون داده می‌شه. پنل و xray-core پنل دست‌نخورده می‌مونن (مسیر و نامشون کاملاً جداست).

**روی کامپیوتر خودت:**
```bash
python3 probe_client.py --uninstall      # ویندوز: py probe_client.py --uninstall
```
تنظیمات، xray-core خصوصی، لاگ‌ها و ورودی شروع خودکار پاک می‌شن. فقط xray‌ای که از پوشه‌ی خود این ابزار اجرا شده بسته می‌شه؛ xrayی که برای v2rayN و مشابه‌هاش داری دست‌نخورده می‌مونه. آخرش چک‌لیست تأیید نشون داده می‌شه و فقط خود فایل `probe_client.py` می‌مونه که دستی حذفش کن.

## عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| Probe Client وصل نمی‌شه | پورت Probe روی فایروال سرور باز باشه (`ufw allow PORT/tcp`) و توکن درست باشه. اگه اپراتور اون پورت رو می‌بنده، پورت ۴۴۳ رو امتحان کن. |
| «Token rejected» | توکن رو دوباره از منوی گزینه‌ی ۲ کپی کن. |
| xray-core روی کامپیوتر دانلود نمی‌شه | دسترسی به GitHub لازمه. می‌تونی `xray` / `xray.exe` رو دستی توی مسیری که برنامه نشون می‌ده بذاری. |
| اپراتور شناسایی‌شده با انتخابت نمی‌خونه | احتمالاً VPN روشنه یا به وای‌فای/اپراتور دیگه‌ای وصلی. |
| مرحله ۲ رد می‌شه | Probe Client وصل نبوده. بدون اون، تست عمیق معنی نداره و اجرا نمی‌شه. |

## محدودیت‌ها (صادقانه)

- نتیجه یه عکس لحظه‌ایه. فیلترینگ زمان‌به‌زمان عوض می‌شه؛ چند بار و در ساعت‌های مختلف تست کن.
- عملکرد یه SNI به **جفتِ (اپراتور، IP سرور)** بستگی داره، نه فقط اپراتور.
- لیست ASNهای داخل پروژه فقط راهنماست. تشخیص اصلی با جستجوی زنده انجام می‌شه.
- تست عمیق عمداً روی ۵۰ دامنه‌ی برتر محدوده تا IP سرورت آسیب نبینه.
